## Workload and measurement

The topology has two 80,000-branch flat maps in series and a 10,000-branch
parent map with eight child branches per parent. Each arithmetic operation is
a separate node. Each ordinary cycle updates 250 flat and 250 child items.
Lifecycle cycles remove or restore flat branches, parent branches, or child
branches. Every 1,000 cycles a shared bias ticks and activates all branches.
The checksum includes additions, changes, and removals.

Runs were sequential, pinned to CPU 31 of an AMD EPYC 7R13 host, and subject
to a 12 GiB process address-space cap. C++ builds were GCC 14.3 Release. BG's
Python runs used CPython 3.13; hgraph runs used CPython 3.12. RSS is a
process-level measure. The graph-run RSS increase is RSS after the final cycle,
before graph stop, minus RSS after workload generation, before graph wiring.
For adapters without a stop hook, the final output event supplies the second
sample. The difference excludes the workload plans resident at the first
sample but can include later process allocations beyond graph storage.
Workload generation happened before graph timing.

The BG Python adapter starts cycle timing in its source callback, after
`test_graph` input dispatch. The corrected current-hgraph adapter starts in a
cycle-control compute node and ends in one outer output sink. It includes
source callbacks and checksum work, but excludes generator prefetch. The
hgraph 0.5 adapter starts in its source callback and its total spans the first
cycle start through the last output event. Both native adapters time one
externally driven outer-graph evaluation per cycle; they use each engine's
normal entry point. The Python adapter differences limit precise cross-engine
ratios. Within-engine arithmetic comparisons keep the same adapter boundary.
No other benchmark process ran concurrently, but host-wide CPU contention was
not controlled. Each category has one 10,000-cycle run; repeat runs would be
needed to estimate run-to-run variance.

BG native used main commit `36eb21fb`; the BG Python lane used
`1c9ad02d71429395b6f728946c4391441ec1846a`. Current hgraph was built
from `de44e25b61dc57e217f9781164eee64b6b77e7cf`; hgraph 0.5 from
`c34dba1db8a1c873ee303796db4c8fc48c8cc5be`. The adapters have since
been integrated into this repository. The current-hgraph C++ adapter was also
corrected to connect its map outputs to top-level sinks, so its integrated
source differs from the measured version. These are historical measurements,
not commit-keyed canonical results: their raw JSON records were held in
temporary storage and are no longer available. Regenerate the raw records
before using them to track performance changes by source commit.
